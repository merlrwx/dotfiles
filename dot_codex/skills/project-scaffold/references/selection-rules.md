# Project scaffold selection rules

| Requirement | Select | Dependency or boundary |
| --- | --- | --- |
| Python API | `python-api` | Python and uv configuration; no UI unless requested |
| Python API plus separate UI | `python-api-with-ui` | API and UI services have independent configuration and checks |
| No supported Python application shape | `generic` | Does not generate a Python application |
| Container build or image delivery | Containers | Compose is a separate choice for local multi-service workflows |
| Isolated editor environment | DevContainer | Optional for Python project types |
| GitHub-hosted repository | GitHub Actions | Tailor triggers and jobs to the project |
| Kubernetes deployment | Kubernetes | Python project types only; container packaging is required |
| GitOps-managed Kubernetes | Flux | Requires Kubernetes, an explicit source repository URL, and an existing Flux controller/reconciliation root |
| Release automation or security scans | Project-specific configuration | Not generated by v1.0.0; add only when requested and validate against the project |

Mise forms the shared development foundation. Python templates provide pytest and Ruff tasks; `generic` stays language-neutral. The template does not add pre-commit hooks, release automation, or security scans by default. Optional modules must not leave broken references when omitted.

For existing repositories, inspect before selecting. Generate into a temporary location, compare against the working tree, and apply changes selectively after review.
